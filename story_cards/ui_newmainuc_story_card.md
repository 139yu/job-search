## 一、一句话版（约 30 秒）

我负责重构了 X-Ray 在线检测设备的主控界面 `NewMainUC`。旧项目仓促开发，团队对 WPF 不熟、规范不足，页面基本是原生样式，模板编辑和 CNC 流程还混在一起，设备问题多、销量低；公司因在线机利润高不想放弃，让我接手。我重新设计了「左中右三栏 + 底部腰带」的布局，把模式拆成自动检测与 2D 模式，并通过权限隔离：普通操作员只进入自动检测模式、只能运行程序。右侧工具条集成了检查点配方、轴控制、相机参数、实时日志、读码导航等工具；菜单按分类组织，还新增了元件库。这个页面的布局和大部分核心功能是我独立设计实现的。

## 二、2 分钟完整版（STAR）

### S 情境

公司 X-Ray 在线检测设备的上位机是旧版页面，项目背景比较复杂：当时项目急、技术选型是 WPF，但团队对 WPF 使用不熟练，开发规范也没有完全遵守，导致已售在线设备大大小小的问题比较多，页面基本是原生样式、布局也不太行，大半年销量约个位数。但在线机利润高，公司不想放弃，一直想优化这个项目。具体到页面本身，主要问题有三个：一是界面难看；二是模板编辑和 CNC 流程共用一个页面，现场操作员在运行界面就能看到模板编辑入口，存在误编辑模板、改坏工艺参数的风险；三是功能入口分散，调试工具和菜单没有统一组织。

### T 任务

我入职不久后，公司知道我会 WPF，先让我美化界面；界面优化过程中又希望完善功能，最终这个在线机重构项目由我负责。我需要重构主工作台，把「能编辑模板」和「只能跑程序」的场景彻底分开：按角色控制可见模式和操作权限；把高频调试功能集中到右侧工具条；菜单按业务分类；同时保证机器运行、回零、报警等状态不能乱切页面。

### A 行动

整个重构从「美化界面」切入，过程中逐步完善功能，最后形成完整的主控界面重构，由我负责设计、实现与落地。

1. 布局重构：采用三列 `350 | * | 550` + 三行 `100 | 50 | *` 网格。左上放 X 光控制，中列放主菜单和模式中心，右列放检测工具；底部腰带放运行日志、模式 Tab、产品流程动画。
2. 模式与权限拆分：拆成自动检测模式与 2D 模式，主壳同时预留 3D 模式扩展。登录后 `IPermissionService` 返回当前角色可用权限键，`IMenuService` 按权限动态生成模式 Tab 和菜单项；一般操作员只有自动检测模式权限，只能运行程序，模板编辑入口对操作员不可见。
3. 右侧工具条：由 `IRightToolCatalog` 描述工具并驱动工具条按钮，新增工具不需要改工具条 XAML。当前工具包括：检查点配方（即预处理配方面板，维护搭配预设 / FOV / 图像预处理 / X 光 / 相机五类参数，组合后可一键下发到设备）、轴控制（Jog、点位运动、速度档、急停、状态互锁、关闭抽屉自动停止）、相机参数、全局倾斜、读码导航、实时日志。
4. 菜单分类：按程序 / 运行 / 运动 / 图像 / 测绘 / 数据 / 设置分类加载，每个菜单项通过 `PermissionKey` 映射到对应 Action，不同角色看到的菜单不同。
5. 中心页与右栏成对导航：切换模式时，中心页和右栏视图一起导航；切换前清理旧模式页遗留的嵌套 Region，避免视图残留和事件泄漏。
6. 安全拦截：`ConfirmNavigationRequest` 拦截离开主壳，`NavigateMainContent` 拦截模式内切换；CNC 运行、回零、报警、急停、绘制未结束都禁止切换。
7. 元件库：新增元件库对话框，维护元件与配方、算法目录与支持检测项、检测类型和分类；元件配方可关联算法并配置检测项上下限。
8. 细节处理：右栏工具抽屉宽度超过 510 时，用统一负 Margin 跨列伸出，解决工具被父容器裁剪的问题；FPD 采集会话通过 `IFpdSessionController` 跟随模式，2D 模式保持实时采集，切走进入空闲，避免两个页面抢相机。

### R 结果

重构后，普通操作员只能看到自动检测模式，运行界面不再暴露模板编辑入口，误编辑模板的风险被权限隔离；调试工具集中到右侧工具条，检查点配方、轴控制、相机参数都能快速调用；菜单按分类组织后功能入口更清楚。后续新增模式和工具主要基于 Region 与工具 Catalog 扩展，主壳不需要大改。从公司角度看，这个项目因为在线机利润高而被保留并持续投入，重构解决了此前设备不好用、页面难看的核心问题；销量提升等业务结果还需要后续数据补充。

## 三、技术亮点（讲给面试官听）

- WPF + Prism 模块化：页面用 `RegionManager` 管理区域，模块在 `SystemMainUIModule` 中注册导航，主壳只负责组合，不直接耦合业务模块。
- 模式 + 权限拆分：核心不是只改 UI，而是把「运行」和「编辑」按角色隔离，普通操作员只进入自动检测模式，只能运行程序。
- 动态 RBAC 菜单：模式 Tab 和主菜单都不是写死的，登录后从权限服务查询并重建。
- 右侧工具 Catalog 驱动：工具条按钮由 `IRightToolCatalog` 投影生成，开闭、互斥、宽度记忆统一管理，新增工具不需要改工具条 XAML。
- 检查点配方：组合预设五分类（搭配 / FOV / 图像预处理 / X 光 / 相机），检查点选择搭配预设后，一键把 FOV、图像预处理、X 光电流电压、扫码相机参数下发到设备。
- 双重重导航保护：离开主壳用 `ConfirmNavigationRequest`，主壳内切换用命令拦截，覆盖运行中误操作场景。
- 生命周期管理：切换模式时清理 `ModeCenterRegion`、`RightPanelRegion` 和模式页拥有的嵌套 Region，防止视图和事件订阅残留。
- FPD 会话控制器：页面不直接操作相机开停，通过 `IFpdSessionController` 表达期望态（Live / Idle / ExclusiveGrab），由控制器收敛硬件实际态，避免多页面抢相机。
- 权限双校验：菜单和右侧工具由权限键过滤可见性，点击执行前再走 `ValidateAndExecute` 运行时校验，不依赖 UI 隐藏。
- 预览与正式参数隔离：算法预览走 `TryBuildPreviewDict` 副本，正式应用走 `BuildComponentAlgoDict`，编辑预览不污染已保存配置。
- 右侧抽屉 overhang（备用细节）：解决 WPF 控件被父容器裁剪的问题，切换模式时统一复位负 Margin，防止状态泄漏到其他页面。

## 四、面试追问准备

### 1. 为什么用 Prism Region 而不是直接放 UserControl？

因为主界面有多个模块：光管、导航、模式中心、右栏工具、设备灯。用 Region 可以让各模块独立注册、独立导航，主壳只负责布局组合，后续加新模式不需要改主壳代码。

### 2. 动态菜单怎么实现的？

登录成功事件触发 `LoadModesForUser` / `LoadMenuForUser`。先用 `_permissionService.GetAvailablePermissionKeys()` 拿到当前角色权限键，再通过 `IMenuService` 过滤菜单项：模式 Tab 用 `GetAllModeItems`，主菜单用 `GetFilteredAll` 并按程序 / 运行 / 运动 / 图像 / 测绘 / 数据 / 设置分类填充；每个菜单项绑 `PermissionKey`，点击时映射到对应 Action。

### 3. 为什么把模板编辑和运行分开？

旧页面把模板编辑和 CNC 流程放在同一个页面，操作员很容易误进编辑入口、误改模板。新页面把自动检测和 2D 模式分开，并通过权限服务过滤模式菜单：一般操作员只有自动检测模式权限，只看到运行程序相关功能，模板编辑入口对其不可见；只有有权限的工程人员才能进入 2D 模式编辑模板。

### 4. 检查点配方是怎么实现的？

右侧「预处理配方」面板维护五类预设：搭配预设、FOV、图像预处理、光管、相机。搭配预设引用子库参数，检查点编辑页通过下拉选择搭配预设，`ComboPresetApplier` 解析组合并下发：FOV 驱动 Z 轴和倾斜偏移，图像预处理写入相机参数，X 光写入电压电流，扫码相机写入曝光和增益；检查点编辑页还有「预处理参数预览」和「同步预处理」到同组检查点。

### 5. 为什么切换页面时要清理嵌套 Region？

每个模式页可能注册自己的子 Region，比如日志、相机显示、CNC 编辑、预处理配方。如果不移除，切换到另一个模式时旧视图还留在 Region 里，会造成视图残留、事件重复订阅和内存泄漏。

### 6. FPD 会话为什么做成控制器收口？

页面不直接控制相机开停，而是通过 `IFpdSessionController` 表达期望态：2D 模式 `EnsureMainLive()`，切走 `EnterIdle()`，标定等场景 `EnterExclusiveGrab(owner)`。控制器是唯一硬件触点，负责把期望态收敛到实际硬件状态，避免多页面抢相机和状态不一致。

### 7. Reconcile 怎么防抖和自愈？

`Reconcile()` 是定时收敛入口：先计算期望目标 `ComputeEffectiveTarget`，再观察实际状态 `ObserveActual`，满足后置条件就结束；不满足就 `ApplyTargetCore` 重试。内部有短采忙跳过、SettleWindow 等待稳定、降级退避防止连环重启，`never-framed` 时强制重开一次。这套状态机有 `FpdSessionControllerTests` 覆盖。

### 8. 右侧工具按钮也做权限校验吗？

做。工具条按钮由 `IRightToolDescriptor.PermissionKey` 控制可见性，点击时 `ModeRightToolShellViewModel.ExecuteOpenTool` 还会调用 `_permissionService.ValidateAndExecute(descriptor.PermissionKey, Open)` 做运行时二次校验，不依赖 UI 隐藏。

### 9. 算法预览为什么不用正式参数？

预览走 `TryBuildPreviewDict`，内部用 `DeepClone` 生成副本再应用 ROI 参数；正式应用走 `BuildComponentAlgoDict` 写回 `DictAlgoPropety`。两条链路隔离，避免编辑预览污染已保存配置。

### 10. 运行中误切页面怎么防？

离开主壳用 `ConfirmNavigationRequest`，主壳内切换用 `NavigateMainContent` 命令拦截；绘制中、运行、回零、报警、急停都禁止切换，并回写 Tab 选中态，防止界面状态和实际模式不一致。

### 11. 右栏被裁剪怎么解决？（备用，面试官问到再讲）

问题来自父容器默认 `ClipToBounds` 行为。解决思路是右栏宿主 `ClipToBounds=False`，抽屉宽度大于 510 时用同一套负 Margin 伸出覆盖到中列；同时加统一 Helper，在切换模式时复位，避免上一次的负 Margin 泄漏到下一个模式页。

### 12. 这个项目为什么交给你负责？

旧在线机虽然利润高，但早期项目急、团队对 WPF 不熟、规范不足，导致设备问题多、页面难用、销量低，公司一直想优化。我入职后，公司知道我有 WPF 经验，先让我美化界面；美化过程中需要完善功能，项目范围逐步扩大，最终由我负责整个主控界面重构。我的优势是既懂 WPF 界面，又熟悉现场运行流程，所以能同时处理布局、权限和运行安全。

### 13. FPD 会话控制器是用 AI 实现的吗？

`FpdSessionController` 是我设计的：接口、状态机边界、owner 独占、防抖自愈、短采恢复这些规则由我定义，编码阶段用了 AI 辅助。面试重点讲设计理由和故障场景；如果被问到实现过程，如实说用了 AI，再补一句“我用单测和现场场景确认行为符合预期”，并准备讲一个具体测试用例。
