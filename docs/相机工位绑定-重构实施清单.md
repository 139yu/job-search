## 第 1 步：`CameraParam` 加入像元尺寸

**文件**：`Vision/Models/CameraParam.cs`（在类里追加一个属性）

```csharp
using Vision.Enums;

namespace Vision.Models;

/// <summary>
/// 相机运行参数模型。
/// 保存相机的采集相关参数配置，可在采集前设置并下发到相机。
/// </summary>
public class CameraParam
{
    // ===== 以下原有字段全部保持不变，各自的 XML 注释请保留 =====
    // ExposureTime / Gain / ImageWidth / ImageHeight
    // StartX / StartY / EndX / EndY / GrabTimeout / ReverseX / ReverseY
    public float ExposureTime { get; set; } = 5000f;
    public float Gain { get; set; } = 1.0f;
    public int ImageWidth { get; set; }
    public int ImageHeight { get; set; }
    public int StartX { get; set; } = 0;
    public int StartY { get; set; } = 0;
    public int EndX { get; set; } = 2048;
    public int EndY { get; set; } = 2048;
    public int GrabTimeout { get; set; } = 1000;
    public bool ReverseX { get; set; } = true;
    public bool ReverseY { get; set; } = true;

    // ===== 新增 =====

    /// <summary>
    /// 相机像元尺寸（单位：微米），用于像素与物理尺寸之间的换算。
    /// <para>
    /// 与上面几项不同，<b>这一项厂商 SDK 不提供，只能人工按相机型号填写</b>；
    /// 也正因如此它<b>不会下发到相机</b>，只在本机参与换算。
    /// </para>
    /// <para>
    /// <b>null 表示尚未填写</b>，换算前必须校验并明确报错，
    /// 不要给默认值——那会让"没填"看起来像"填了"，算出一个看起来正常的错误结果。
    /// </para>
    /// </summary>
    public double? PixelSize { get; set; }
}
```

> ⚠️ 上面原有字段的 XML 注释我用一行 `//` 概括了。**粘贴时保留你文件里原有的 `<summary>`**，只把 `PixelSize` 那一段追加进去。

### 为什么用 `double?` 而不是 `double`

`double` 必须有值，就会被迫给个默认（比如原来 `CameraInfo` 里的 `3.45`）。一旦有默认值，**用户忘了填时程序不会报错，而是拿 3.45 算出一个"看起来完全正常"的测量结果**。

`double?` 让"没填"成为一个**可以被检查出来的状态**。

> **XML 注释里的 `<para>`**：`<summary>` 里要分段时用 `<para>...</para>` 包起来，IDE 的悬浮提示会正确换行。不加的话多段文字会挤成一行。

## 第 4 步：重写 `StationProfile`

**文件**：`Vision/Models/StationProfile.cs`（整个替换）

```csharp
using Vision.Enums;

namespace Vision.Models;

/// <summary>
/// 工位配置。
/// 描述一个工位绑定了哪台相机，以及该工位的相机参数。
/// </summary>
public class StationProfile
{
    /// <summary>工位名称。工位的唯一标识。</summary>
    public StationEnum StationName { get; set; }

    // ==================== 身份：绑定的定义 ====================
    // 这两项一起唯一确定一台设备，二者任一为 null 即表示"未绑定"。
    //
    // 为什么只存"身份"而不存整个 CameraInfo：
    // CameraInfo 里其余字段（名称/型号/接口）都是枚举一次就能拿到的固件信息，
    // 存进配置文件只会在换机、换驱动、升级固件之后变成过时的假数据，
    // 而且没有任何机制会去更新它。

    /// <summary>绑定的相机品牌。决定用哪个 SDK 打开。null = 未绑定。</summary>
    public CameraEnum? CameraType { get; set; }

    /// <summary>绑定的相机序列号。null = 未绑定。</summary>
    public string? SerialNum { get; set; }

    // ==================== 人工配置 ====================

    /// <summary>
    /// 本工位的相机参数。
    /// 参数属于工位而不属于相机——同一台相机插到不同工位，曝光/增益本来就该是两套配置。
    /// </summary>
    public CameraParam Param { get; set; } = new();

    // ==================== 描述缓存：仅供设备离线时显示 ====================
    // 相机没插的时候枚举不出来，但界面上"这个工位本来绑的是哪个型号"仍然值得显示。
    // 打开成功后必须以枚举结果覆盖这里，保证同一份事实只有一个权威。

    /// <summary>相机型号缓存。仅供设备离线时在界面上显示，不参与任何逻辑判断。</summary>
    public string? TypeModel { get; set; }

    // ==================== 派生属性 ====================

    /// <summary>
    /// 是否已绑定。
    /// <para>
    /// 派生自身份字段，<b>不单独存状态</b>——存两份必然不同步
    /// （原来的 <c>IsBinding</c> 字段就是这个问题：从没被赋过值，导致配置里明明有绑定，
    /// 界面上也永远显示"未绑定"）。
    /// </para>
    /// </summary>
    public bool IsBound => CameraType is not null && SerialNum is not null;

    /// <summary>
    /// 绑定标识，形如 <c>HikVision/DB0147821</c>。
    /// 用于日志输出和重复绑定判断，避免在多处各拼一遍字符串。
    /// </summary>
    public string BindingKey => IsBound ? $"{CameraType}/{SerialNum}" : string.Empty;
}
```

### 为什么序列号要和品牌一起判断

`SerialNum` 只在**同一品牌内**唯一。将来接入巴斯勒，理论上可能出现两台不同品牌相机序列号相同。所以绑定标识用 `(CameraType, SerialNum)` **组合**表达，判断时两个都要比。

> **`=>` 表达式体成员**：`public bool IsBound => 表达式;` 是只读属性的简写，等价于 `{ get { return 表达式; } }`。只读属性一律用这个写法，一眼能看出"它没有存储、每次算出来的"。

> **`is not null` / `is null`**：C# 9 的模式匹配写法，和 `!= null` / `== null` 效果相同但更安全——它不会调用可能被重载的 `==` 运算符，对可空值类型也是同一个写法。

> **`$"{CameraType}/{SerialNum}"`**：插值字符串，`$` 前缀表示可以在 `{}` 里直接写表达式。等价于 `string.Format("{0}/{1}", ...)`，但不用管参数顺序。

## 第 5 步：`CameraFactory` 拆掉打包盒

**文件**：`Vision/Factory/CameraFactory.cs`（整个替换）

```csharp
using Commons.Base;
using Vision.Base;
using Vision.Camera;
using Vision.Enums;
using Vision.Models;

namespace Vision.Factory;

/// <summary>
/// 相机设备工厂。按品牌创建对应的 <see cref="ICameraDevice"/> 实现。
/// </summary>
public class CameraFactory
{
    public static readonly CameraFactory Instance;

    static CameraFactory()
    {
        Instance = new CameraFactory();
    }

    private CameraFactory()
    {
    }

    /// <summary>
    /// 创建相机设备实例。
    /// </summary>
    /// <param name="cameraInfo">设备信息。至少要有 <c>CameraType</c>（决定用哪个 SDK）和 <c>SerialNum</c>（决定连哪台）。</param>
    /// <param name="cameraParam">该工位的相机参数。</param>
    /// <exception cref="BusinessException">设备信息或参数缺失，或品牌不受支持。</exception>
    public ICameraDevice Create(CameraInfo cameraInfo, CameraParam cameraParam)
    {
        if (cameraInfo is null)
            throw new BusinessException("设备信息不能为空");
        if (cameraParam is null)
            throw new BusinessException("相机参数不能为空");

        return cameraInfo.CameraType switch
        {
            CameraEnum.HikVision => new HikVisionCamera(cameraInfo, cameraParam),

            // 下划线 _ 是"弃元"，相当于 switch 的 default 分支。
            // 写成 throw 表达式可以省掉一个 return，编译器也能确认所有路径都有返回值。
            _ => throw new BusinessException("不支持的相机品牌：" + cameraInfo.CameraType)
        };
    }
}
```

### 为什么这次改动这么小

因为 `HikVisionCamera`、`ICameraDevice`、`CameraInfo`、`CameraParam` **全都不用动**。

- `ICameraDevice` 是**接口**，接口里没有构造函数，只有方法声明——所以"接口的构造方法要改"这件事本身不成立。
- `HikVisionCamera` 的构造函数本来就是 `(CameraInfo, CameraParam)` 两个独立参数。

**变的只是 `CameraInfo` 从哪来**：以前从配置文件反序列化得到一个完整的 `CameraInfo`，以后从硬件枚举得到。

> **`switch` 表达式**（C# 8）：`值 switch { 模式 => 结果, _ => 结果 }`。它是一个**表达式**（有值），不是语句，所以可以直接 `return`，比传统 `switch` 少写一堆 `case`/`break`。

> **`_ => throw ...`**：`throw` 在 C# 7 之后是**表达式**，可以出现在任何需要值的位置。所以能塞在 `switch` 的分支里。

## 第 6 步：新增 `StationConnectionState`

**文件**：新建 `Vision/Enums/StationConnectionState.cs`

```csharp
namespace Vision.Enums;

/// <summary>
/// 工位与相机的连接状态。
/// </summary>
public enum StationConnectionState
{
    /// <summary>该工位尚未绑定相机。</summary>
    Unbound,

    /// <summary>已绑定，且相机已成功连接。</summary>
    Connected,

    /// <summary>
    /// 已绑定，但设备不在线——配置里有序列号，硬件上枚举不到。
    /// 通常是没插、没上电、或网线没接。
    /// </summary>
    Offline,

    /// <summary>
    /// 已绑定，设备也在线，但打开失败。
    /// 通常是被别的程序占用、或初始化（下发参数）失败。
    /// </summary>
    Failed
}
```

### 为什么要四种状态

原来的 `OpenCamera()` 返回 `void`，失败只记日志，**界面上只能显示"未绑定"**——把三件完全不同的事混成了一件。

而这三种情况**操作员要做的事完全不同**：

| 状态 | 操作员该做什么 |
|---|---|
| `Unbound` | 去设置页绑定一台 |
| `Offline` | 去插线 / 开电源 |
| `Failed` | 去关掉占用设备的那个程序 |

只给一个"没连上"，操作员只能瞎猜。

> **`Last` 这个成员不要加**：C# 里 `Enum.GetValues` 和 `switch` 都不需要哨兵值，加了反而要处理"遍历时跳过 Last"这种额外逻辑。

## 第 7 步：重写 `ICameraStationService`

**文件**：`Vision/Base/ICameraStationService.cs`（整个替换）

```csharp
using Vision.Enums;
using Vision.Models;

namespace Vision.Base;

/// <summary>
/// 工位与相机的装配服务。
/// 负责三件事：加载工位配置、按工位打开/关闭相机、维护工位与相机的绑定关系。
/// </summary>
public interface ICameraStationService
{
    // ==================== 启动初始化 ====================

    /// <summary>
    /// 初始化：加载工位配置，并按配置打开所有已绑定的相机。
    /// <para><b>程序启动时调用一次</b>；设置页里"重新连接"也可以调它。</para>
    /// <para>
    /// <b>这是耗时操作</b>（枚举 + 打开 + 初始化，通常几百毫秒到数秒），
    /// 调用方应当在后台线程执行，或用等待窗包住。
    /// </para>
    /// </summary>
    /// <returns>各工位的连接状态，供启动日志和状态栏使用。</returns>
    IReadOnlyDictionary<StationEnum, StationConnectionState> Initialize();

    // ==================== 配置 ====================

    /// <summary>
    /// 当前工位配置。在 <see cref="Initialize"/> 或 <see cref="LoadStations"/> 之前是空集合。
    /// <para><b>只读</b>：要改绑定关系请用 <see cref="Bind"/> / <see cref="Unbind"/>。</para>
    /// </summary>
    IReadOnlyList<StationProfile> Stations { get; }

    /// <summary>加载工位配置（<b>不碰设备</b>）。首次运行时补齐全部默认工位。</summary>
    IReadOnlyList<StationProfile> LoadStations();

    /// <summary>保存当前工位配置。</summary>
    void SaveStations();

    // ==================== 设备：按工位粒度 ====================

    /// <summary>
    /// 打开某工位绑定的相机。
    /// <para><b>幂等</b>：重复调用会先关掉旧的再打开。</para>
    /// </summary>
    /// <returns>本次打开后的连接状态。</returns>
    StationConnectionState OpenStation(StationEnum station);

    /// <summary>关闭某工位的相机。该工位没有打开的相机时是空操作。</summary>
    void CloseStation(StationEnum station);

    /// <summary>查询某工位当前的连接状态。<b>不触发任何操作</b>。</summary>
    StationConnectionState GetConnectionState(StationEnum station);

    /// <summary>取某工位已连接的相机设备。</summary>
    /// <exception cref="BusinessException">该工位未绑定，或相机未连接。</exception>
    ICameraDevice GetCamera(StationEnum station);

    // ==================== 绑定关系 ====================

    /// <summary>
    /// 把相机绑定到工位。
    /// <para>一台设备只能属于一个工位——该相机若已绑在别的工位，会先从原工位解绑。</para>
    /// </summary>
    void Bind(StationEnum station, CameraInfo camera);

    /// <summary>解除某工位的绑定，并关闭它已打开的相机。</summary>
    void Unbind(StationEnum station);
}
```

### 为什么保留了 `Initialize()`，而没有像上一版那样删掉"开全部"

上一版我论证了"全部打开 = 逐个打开的三行循环"，然后把 `OpenCamera()` 整个删掉了。**那是过头了**——原来的问题是它的**实现**（`if`/`else` 把"补默认工位"和"打开相机"对立起来，导致首次运行一行都不执行），不是它**该不该存在**。

"启动时按配置把所有工位接上"是一个**确定存在的、唯一的场景**，而且它就是服务的职责。推给调用方写循环，等于让这个必须发生的动作散落在外面。

**真正要拆开的是职责，不是删掉入口**：

| 方法 | 职责 |
|---|---|
| `LoadStations()` | 只处理**配置**（读文件 + 补默认工位），不碰设备 |
| `Initialize()` | 配置 + 设备一起：先 `LoadStations()`，再逐个 `OpenStation()` |

想单独拿配置（比如设置页只刷新列表）就调 `LoadStations()`；走完整启动流程就调 `Initialize()`。

### 为什么 `OpenStation` 返回状态枚举而不是 `bool`

`bool` 只知道"成没成"，界面上就无法区分 `Offline` 和 `Failed`——而这两种情况操作员要做的事完全不同（见第 6 步）。

顺带，`StationConnectionState` 也替代了原来的 `IsStationOnline(station)`：**一个查询状态的方法就够了，不需要"是否在线"+"打开结果"两套并行**。

## 第 8 步：重写 `CameraStationService`

**文件**：`Vision/Service/CameraStationService.cs`（整个替换）

```csharp
using Commons.Base;
using Commons.Enums;
using Commons.Logging;
using Vision.Base;
using Vision.Camera;
using Vision.Enums;
using Vision.Factory;
using Vision.Models;

namespace Vision.Service;

/// <summary>
/// 工位与相机的装配服务。
/// </summary>
public class CameraStationService : ICameraStationService
{
    private static readonly NLog.Logger Logger = Log.For<CameraStationService>(LogModule.Camera);

    private readonly ICameraConfigStore _cameraConfigStore;

    /// <summary>
    /// 工位配置。
    /// 由 <see cref="LoadStations"/> 填充，之后一律<b>原地修改</b>，绝不整体替换——
    /// 一替换，上层界面拿着的旧对象就全部失联了。
    /// </summary>
    private List<StationProfile> _stationProfiles = new();

    /// <summary>已打开的相机设备，键为工位。</summary>
    private readonly Dictionary<StationEnum, ICameraDevice> _cameraDict = new();

    public CameraStationService(ICameraConfigStore cameraConfigStore)
    {
        _cameraConfigStore = cameraConfigStore;
    }

    // ==================== 启动初始化 ====================

    /// <inheritdoc/>
    public IReadOnlyDictionary<StationEnum, StationConnectionState> Initialize()
    {
        LoadStations();

        var result = new Dictionary<StationEnum, StationConnectionState>();

        // 逐个工位打开。某个工位失败不影响其它工位——
        // 一台相机没插上，不该让另一台也用不了。
        foreach (var profile in _stationProfiles)
            result[profile.StationName] = OpenStation(profile.StationName);

        return result;
    }

    // ==================== 配置 ====================

    /// <inheritdoc/>
    public IReadOnlyList<StationProfile> Stations => _stationProfiles;

    /// <inheritdoc/>
    public IReadOnlyList<StationProfile> LoadStations()
    {
        _stationProfiles = _cameraConfigStore.LoadStations() ?? new List<StationProfile>();

        // 补齐缺失的工位：首次运行时配置为空，或将来 StationEnum 新增了成员。
        // 注意是"缺哪个补哪个"，不是"重建整个列表"——重建会丢掉已有的绑定关系和参数。
        foreach (StationEnum value in Enum.GetValues(typeof(StationEnum)))
        {
            if (_stationProfiles.All(x => x.StationName != value))
                _stationProfiles.Add(new StationProfile { StationName = value });
        }

        return _stationProfiles;
    }

    /// <inheritdoc/>
    public void SaveStations()
    {
        _cameraConfigStore.SaveStations(_stationProfiles);
    }

    // ==================== 设备 ====================

    /// <inheritdoc/>
    public StationConnectionState OpenStation(StationEnum station)
    {
        // 幂等：先关掉可能已经打开的实例，避免同一个工位挂上两个设备对象。
        CloseStation(station);

        var profile = FindProfile(station);
        if (profile is null || !profile.IsBound)
            return StationConnectionState.Unbound;

        ICameraDevice? device = null;
        try
        {
            // 按配置里的"身份"，从硬件重新枚举出完整信息。
            var info = ResolveCameraInfo(profile);
            if (info is null)
            {
                // 配置里有绑定，但硬件上枚举不到——这是"离线"，不是"未绑定"。
                Logger.Warn($"[CameraStation] 设备不在线: station={station}, sn={profile.SerialNum}");
                return StationConnectionState.Offline;
            }

            device = CameraFactory.Instance.Create(info, profile.Param);
            device.Open();
            device.Init();

            _cameraDict[station] = device;
            Logger.Info($"[CameraStation] 已连接: station={station}, sn={info.SerialNum}");
            return StationConnectionState.Connected;
        }
        catch (Exception e)
        {
            Logger.Error(e, $"[CameraStation] 打开失败: station={station}, sn={profile.SerialNum}");

            // 清理半开状态。CloseQuietly 自己吞掉异常，
            // 否则"关闭失败"会盖掉上面刚记下的"打开失败"。
            CloseQuietly(device);
            _cameraDict.Remove(station);
            return StationConnectionState.Failed;
        }
    }

    /// <inheritdoc/>
    public void CloseStation(StationEnum station)
    {
        if (!_cameraDict.TryGetValue(station, out var device))
            return;

        // 先从字典里摘掉，再关设备。反过来的话，假如 Close() 内部又回调到本服务，
        // 字典里还留着这个正在关闭的实例。
        _cameraDict.Remove(station);
        CloseQuietly(device);
    }

    /// <inheritdoc/>
    public StationConnectionState GetConnectionState(StationEnum station)
    {
        var profile = FindProfile(station);
        if (profile is null || !profile.IsBound)
            return StationConnectionState.Unbound;

        if (!_cameraDict.TryGetValue(station, out var device))
            return StationConnectionState.Offline;

        return device.State == CameraStateEnum.Disconnected
            ? StationConnectionState.Offline
            : StationConnectionState.Connected;
    }

    /// <inheritdoc/>
    public ICameraDevice GetCamera(StationEnum station)
    {
        if (GetConnectionState(station) == StationConnectionState.Connected)
            return _cameraDict[station];

        throw new BusinessException($"工位 {station} 的相机未连接。");
    }

    // ==================== 绑定关系 ====================

    /// <inheritdoc/>
    public void Bind(StationEnum station, CameraInfo camera)
    {
        var target = FindProfile(station)
                     ?? throw new BusinessException($"找不到工位 {station}");

        // 一台设备只能属于一个工位：先把可能存在的旧绑定摘掉。
        // 不做这一步的话，配置文件里会出现两个工位指向同一个序列号，
        // 下次启动时两个工位会去抢同一个物理设备——海康 SDK 只允许一个句柄打开同一台设备，
        // 后开的会失败，而且失败原因看起来像"设备被占用"，很难联想到是配置重复。
        foreach (var other in _stationProfiles.Where(x => x.StationName != station))
        {
            if (other.CameraType == camera.CameraType && other.SerialNum == camera.SerialNum)
            {
                CloseStation(other.StationName);   // 旧工位的设备也要关掉
                other.CameraType = null;
                other.SerialNum = null;
                other.TypeModel = null;

                Logger.Info($"[CameraStation] 相机已从原工位解绑: sn={camera.SerialNum}, from={other.StationName}");
            }
        }

        // 只写"身份"，以及离线显示用的型号。其余字段交给枚举。
        target.CameraType = camera.CameraType;
        target.SerialNum = camera.SerialNum;
        target.TypeModel = camera.TypeModel;

        SaveStations();

        // 绑定完立刻尝试打开，让用户当场就知道能不能连上，而不是等到下次启动。
        OpenStation(station);
    }

    /// <inheritdoc/>
    public void Unbind(StationEnum station)
    {
        var profile = FindProfile(station);
        if (profile is null)
            return;

        CloseStation(station);

        profile.CameraType = null;
        profile.SerialNum = null;
        profile.TypeModel = null;

        // 注意：Param 不清空。
        // 参数属于工位，解绑相机不代表这个工位的参数配置作废——
        // 换一台同型号相机插上来，参数往往可以直接沿用。
        SaveStations();

        Logger.Info($"[CameraStation] 已解绑: station={station}");
    }

    // ==================== 私有工具 ====================

    private StationProfile? FindProfile(StationEnum station)
        => _stationProfiles.FirstOrDefault(x => x.StationName == station);

    /// <summary>
    /// 按配置里的品牌和序列号，从硬件重新枚举出当前的设备信息。
    /// </summary>
    /// <returns>找到则返回完整信息；设备没插或未绑定则返回 null。</returns>
    private CameraInfo? ResolveCameraInfo(StationProfile profile)
    {
        // 显式判空同时完成两件事：类型收窄（CameraType 从 CameraEnum? 变成 CameraEnum）
        // 和短路返回，比写两行 if 更紧凑。
        if (profile.CameraType is null || profile.SerialNum is null)
            return null;

        var enumerator = CameraEnumeratorFactory.Instance.GetCameraEnumerator(profile.CameraType.Value);

        // 不要写成 Any() + FirstOrDefault()，直接 FirstOrDefault() 一次遍历就够。
        return enumerator.ListAvailable()
                         .FirstOrDefault(x => x.SerialNum == profile.SerialNum);
    }

    /// <summary>
    /// 关闭设备，失败只记日志。
    /// <para>
    /// <b>关键：这里绝不能再往外抛。</b>本方法主要在 <c>catch</c> 块里被调用，
    /// 若它自己抛异常，就会把外面刚捕获的原始失败原因整个盖掉，
    /// 排查时只能看到"关闭失败"，看不到"为什么打开失败"。
    /// </para>
    /// </summary>
    private static void CloseQuietly(ICameraDevice? device)
    {
        if (device is null)
            return;

        try
        {
            // 已经断开的不必再关，避免 SDK 抛出无意义的错误。
            if (device.State != CameraStateEnum.Disconnected)
                device.Close();
        }
        catch (Exception e)
        {
            Logger.Error(e, "[CameraStation] 关闭设备失败");
        }
    }
}
```

### 三个关键设计点的原因

**① 启动连接必须"逐个独立"，一个失败不能拖垮其它的**

`Initialize()` 里是 `foreach` 逐工位调用，每个工位内部各自 `try`/`catch`。所以一台相机没插上（`Offline`），**不影响另一台正常连上**。

如果写成"整体 try/catch"，第一台抛异常后面的循环就断了——这正是原来 `OpenCamera()` 隐藏的坑之一。

**② `_stationProfiles` 原地修改，绝不整体替换**

原来的 `OpenCamera()` 里有 `_stationProfiles = _cameraConfigStore.LoadStations();`——**把整个 List 换成新的**。而上层界面构造时抓的是旧引用，这一换，界面上的东西全部失联，改了也不显示。

现在 `LoadStations()` 只在初始化和"重新加载"时被调用，`Bind`/`Unbind` 都是原地改字段。

**③ `Bind` 里要先把相机从别的工位摘掉**

见上面代码注释里那段——重复绑定会让下次启动时两个工位去抢同一个物理设备。

## 第 9 步：启动接线

**文件**：`MainApp/ViewModels/MainWindowViewModel.cs`（整个替换）

```csharp
using System;
using System.Threading.Tasks;
using System.Windows;
using Commons;
using Commons.Base;
using Commons.Enums;
using Commons.Logging;
using CommonUI.Helper;
using CommonUI.Service;
using MainApp.Views;
using Vision.Base;

namespace MainApp.ViewModels
{
    public class MainWindowViewModel : BindableBase
    {
        private static readonly NLog.Logger _logger = Log.For<MainWindowViewModel>(LogModule.App);

        private readonly IRegionManager _regionManager;
        private readonly IEventAggregator _eventAggregator;
        private readonly ICameraStationService _cameraStationService;
        private readonly IBusyService _busyService;

        public MainWindowViewModel(IRegionManager regionManager,
                                   IEventAggregator eventAggregator,
                                   ICameraStationService cameraStationService,
                                   IBusyService busyService)
        {
            _logger.Debug("程序启动");
            _regionManager = regionManager;
            _eventAggregator = eventAggregator;
            _cameraStationService = cameraStationService;
            _busyService = busyService;

            CloseCommand = new DelegateCommand(DoCloseCommand);

            // 由 MainWindow.xaml.cs 的 Loaded 里发布，此时窗口已经显示出来了
            _eventAggregator.GetEvent<AppLoadedEvent>().Subscribe(AppLoaded);
        }

        private string title = "Nobody";

        public string Title
        {
            get { return title; }
            set { title = value; }
        }

        public DelegateCommand CloseCommand { get; set; }
        public DelegateCommand LoadedCommand { get; set; }

        private void DoCloseCommand()
        {
            Application.Current.MainWindow.Close();
        }

        private void AppLoaded()
        {
            // 先铺界面，让用户尽快看到主窗体
            _regionManager.RequestNavigate(RegionConstants.HalconRegion, "HwView");
            _regionManager.RequestNavigate(RegionConstants.MainMenuRegion, "MainMenuView");

            // 再按配置自动连接相机。
            //
            // 刻意不 await：连接可能几秒，不该拖住界面导航。
            // 用 `_ =` 显式表示"这个 Task 我有意丢弃"——
            // 异常已经在 ConnectCamerasAsync 内部处理，不会变成未观察异常。
            _ = ConnectCamerasAsync();
        }

        /// <summary>
        /// 按配置打开所有已绑定的工位相机。
        /// </summary>
        private async Task ConnectCamerasAsync()
        {
            try
            {
                // 用不可中断的请求：启动时的相机连接是必须完成的，
                // 给用户一个"取消"只会让他进到主界面却没有相机可用。
                // 快的话（< ShowDelayMs）等待窗根本不会出现。
                var states = await _busyService.RunAsync(
                    BusyRequest.BlockingRequest("正在连接相机…"),
                    (progress, ct) => _cameraStationService.Initialize());

                foreach (var pair in states)
                    _logger.Info($"[App] 工位连接结果: station={pair.Key}, state={pair.Value}");
            }
            catch (Exception ex)
            {
                // 连接失败不该阻断程序启动——用户至少要能进界面去手动排查
                _logger.Error(ex, "启动时连接相机失败");
                GrowlHelper.Error("连接相机失败，详情见日志");
            }
        }
    }
}
```

### 为什么用 `_ = ConnectCamerasAsync()` 而不是 `async void`

`AppLoaded` 是 `PubSubEvent.Subscribe(Action)` 的回调，签名必须是 `void`。两种写法都能让它变成异步：

| 写法 | 问题 |
|---|---|
| `private async void ConnectCamerasAsync()` | 方法内部的异常若逃出去，会直接击穿到 Dispatcher，**进程崩溃**；而且调用方无从知道它什么时候结束 |
| `private async Task ConnectCamerasAsync()` + 调用处 `_ =` | 异常在方法内部 `try/catch` 处理；`_ =` 明确表明"有意不等它" |

两者行为上差不多（都靠内部 catch 兜住），但 `async Task` 的签名能让人一眼看出"这是个异步方法"，而且将来想改成 `await` 或加超时都不用改签名。

> **`_ = 表达式`**：下划线是**弃元**，表示"这个返回值我不要"。加它不是语法要求，而是给读代码的人一个信号——**"这里确实是有意不 await 的，不是漏了"**。不加也能编译，但会被当成 bug 来找。

### 为什么放在 `AppLoaded` 而不是 `App.OnInitialized`

`AppLoadedEvent` 由 `MainWindow.xaml.cs` 在窗口的 `Loaded` 事件里发布——**那一刻主窗体已经显示出来了**。所以：

- 等待窗有 `Owner` 可以挂（不会再出现"没有宿主窗口"的情况）
- 用户先看到主界面，再看到"正在连接相机…"，观感是对的

如果在 `App.OnInitialized` 里做，窗口还没创建，等待窗没有 Owner，而且启动会**先白屏几秒**。

### 关于等待窗

这里复用了第 8 步之前做好的 `IBusyService`——**启动连接相机本来就是个耗时操作**，正好是它的用武之地。

- 快（枚举+打开 < `ShowDelayMs`）→ 等待窗根本不出现
- 慢 → 出现"正在连接相机…"，连完自动关

注意用的是 `BlockingRequest`（不可中断）：这是启动必备步骤，不该给用户"取消"。

## 语法糖速查

本次用到的、不太常见写法汇总：

| 写法 | 名称 | 含义 | 等价于 |
|---|---|---|---|
| `a ?? b` | null 合并 | `a` 为 null 时取 `b` | `a != null ? a : b` |
| `a ?? throw e` | null 合并 + throw 表达式 | `a` 为 null 时抛异常 | `if (a == null) throw e;` |
| `is null` / `is not null` | 模式匹配 | 判空 | `== null` / `!= null`，但不走重载的 `==` |
| `值 switch { 模式 => 结果, _ => 结果 }` | switch 表达式 | 有返回值的多分支 | 传统 `switch` + `return` |
| `_` | 弃元 | "这个位置我不关心" | — |
| `_ = expr` | 弃元赋值 | "这个返回值我有意丢弃" | — |
| `=> 表达式` | 表达式体成员 | 只读属性/单行方法的简写 | `{ get { return ...; } }` |
| `$"{x}"` | 插值字符串 | 字符串里直接写表达式 | `string.Format` |
| `CameraEnum?` | 可空值类型 | 值类型允许为 null | `Nullable<CameraEnum>` |
| `new()` | 目标类型推断 | 从左边声明推断类型 | `new List<StationProfile>()` |
| `profile.CameraType.Value` | 可空取值 | 从 `CameraEnum?` 取出 `CameraEnum` | — |

> **`foreach (StationEnum value in Enum.GetValues(typeof(StationEnum)))`**
> `Enum.GetValues` 返回的是**非泛型 `Array`**，元素是 `object`。C# 的 `foreach` 允许在循环变量上写具体类型，编译时会自动插入强制转换。
> .NET 5+ 还有泛型版本 `Enum.GetValues<StationEnum>()`，能直接拿到 `StationEnum[]`，但当前写法在 net6.0 上也完全没问题。
